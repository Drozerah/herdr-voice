# 006_ADR: Outil de Rechargement Automatique pour le Serveur de Mock (nodemon)

- **Statut :** Accepté (Accepted)
- **Auteurs :** Thomas Gauthier & Antigravity (Google DeepMind Team)
- **Date :** 2026-07-26
- **Version du Plugin :** v1.0.0-alpha.1

---

## 1. Contexte & Problématique

Lors du développement du serveur factice d'inférence TTS (`bin/mock-tts-server.js`), toute modification de code nécessite un redémarrage du processus HTTP pour être prise en compte.

Un redémarrage manuel répété ralentit la boucle de rétroaction du développeur. Il est nécessaire de disposer d'un outil de rechargement automatique à chaud (Hot Reload) souple, éprouvé et configurable.

---

## 2. Décisions d'Architecture

### D1. Adoption de `nodemon` en Dépendance de Développement
- **Choix :** Le package `nodemon` est installé en dépendance dev (`devDependencies`) pour assurer le rechargement automatique du serveur de mock lors de l'édition du code.
- **Raison du Choix :** `nodemon` offre une souplesse supérieure pour la gestion fine des extensions de fichiers surveillées, l'exclusion de répertoires temporaires et le traitement propre des signaux POSIX (`SIGINT` / `SIGTERM`).

### D2. Commande NPM Dédiée
- **Script :** Le script `"mock-tts": "nodemon bin/mock-tts-server.js"` est enregistré dans le fichier `package.json`.

---

## 3. Conséquences

### Positives :
- Confort de développement maximal : modification et rechargement instantanés du serveur Mock TTS sans intervention manuelle.
- Dépendance strictement isolée dans les `devDependencies` (aucun impact sur la taille du bundle distribué `dist/index.js`).
