# 014_ADR: Normalisation de la Configuration par IETF JSON Schema (Draft 2020-12) et Validation Ajv

- **Statut :** Accepté (Accepted)

## 1. Contexte & Problématique

Pour garantir un niveau de qualité rigoureux et offrir une expérience utilisateur facilitée, le plugin `herdr-voice` doit valider son fichier déclaratif de configuration `herdr-plugin.toml` sans recourir à des valeurs écrites en dur dans le code source.

La configuration doit être strictement validée par un schéma normalisé reconnu par les éditeurs (VS Code, Antigravity IDE) tout en protégeant l'utilisateur contre les surcoûts d'inférence (emballement d'agents IA) et les plantages réseau.

---

## 2. Décisions d'Architecture

### D1. Normalisation par le Schéma Officiel IETF JSON Schema (Draft 2020-12)
- Le contrat de configuration du plugin est formalisé dans le fichier de schéma officiel **`schemas/herdr-plugin.schema.json`** conforme à la norme **IETF JSON Schema Draft 2020-12**.
- Ce schéma garantit l'autocomplétion en direct et le surlignage des erreurs dans les IDEs.

### D2. Validation par le Moteur Ajv (Another JSON Schema Validator)
- La validation dynamique de la configuration dans `src/config.js` est déléguée à la bibliothèque **Ajv** et ses plug-ins de formats (`ajv-formats`).
- Les erreurs de validation Ajv sont restituées sous forme d'un tableau d'erreurs d'une précision chirurgicale (`instancePath`, `message`).
  - **Exemple de tableau d'erreurs formaté par `src/config.js` :**
    ```javascript
    [
      "Configuration error at [server.endpoint]: must match format \"uri\"",
      "Configuration error at [server.speed]: must be >= 0.25"
    ]
    ```

### D3. Structure TOML Explicite, Master Toggle & Garde-Fous de Sécurité
Le fichier `herdr-plugin.toml` se compose des sections suivantes :
1. **`[plugin]` :** `name`, `version`, `enabled` (Interrupteur *Master Toggle* booléen) :
   - **Fonctionnement de `enabled` (`true` par défaut, `false` pour désactiver) :**  
     Lorsque `enabled = false` (dans `herdr-plugin.toml` ou via `HERDR_VOICE_ENABLED=false`), `src/config.js` enregistre une trace d'information discrète (`[HERDR-VOICE] Plugin désactivé par la configuration`). Les écouteurs d'événements textuels de `src/index.js` s'interrompent immédiatement : aucune requête réseau HTTP n'est émise et aucun lecteur `@audio/speaker` n'est instancié (consommation CPU/RAM/Réseau = 0 %). L'utilisateur peut ainsi couper la voix du plugin à tout moment sans le désinstaller de Herdr.
   
   > [!IMPORTANT] **Directive de Sécurité Immuable (Short-Circuit Evaluation) :**
   > Tant que `enabled` n'est pas égal à `true` (ou en cas de `enabled = false`), le plugin **ne doit consommer STRICTEMENT AUCUNE ressource** (0 octet de buffer RAM audio alloué, 0 traitement de chaînes de caractères, 0 requête d'inférence HTTP). La vérification du champ `enabled` doit impérativement s'effectuer en **évaluation court-circuit (*Short-Circuit Evaluation*) au tout premier niveau d'entrée de `src/index.js`**, en amont de toute invocation des modules réseau ou audio.
2. **`[server]` :** `endpoint`, `api_key`, `model`, `voice`, `speed`, `response_format`.
3. **`[server]` (Garde-fous) :**
   - `max_input_length` (défaut `1000`) : Tronque le texte si un agent IA génère un volume d'entrée excessif.
   - `max_requests_per_minute` (défaut `10`) : Disjoncteur automatique contre les boucles d'inférence infinies.
4. **`[audio]` :** `sample_rate` (`24000`), `channels` (`1`), `high_water_mark` (`16384` octets RAM).
5. **`[extra_headers]` & `[extra_body]` :** Extensions universelles pour la compatibilité avec tout l'écosystème d'inférence (Standard OpenAI SDK).

  - **Exemple de structure `herdr-plugin.toml` :**
    ```toml
    [plugin]
    name = "herdr-voice"
    version = "1.0.0-alpha.1"
    enabled = true

    [server]
    endpoint = "http://127.0.0.1:8888/v1/audio/speech"
    api_key = ""
    model = "mlx-kokoro"
    voice = "Thomas"
    speed = 1.0
    response_format = "aiff"
    max_input_length = 1000
    max_requests_per_minute = 10

    [audio]
    sample_rate = 24000
    channels = 1
    high_water_mark = 16384

    [extra_headers]
    # "OpenAI-Organization" = "org-123456789"

    [extra_body]
    # stability = 0.75
    ```

### D4. Journalisation Universelle & Notifications Toast UI Herdr
- Le module **`src/logger.js`** assure une double émission :
  - **Traces Système Herdr :** Les logs horodatés au format ISO (`[HH:MM:SS] [HERDR-VOICE] [INFO/WARN/ERROR]`) émis sur les flux standard (`console.log`, `console.warn`, `console.error`) sont capturés par le multiplexeur Herdr et exportés dans le fichier de log système réservé aux extensions :
    - **Emplacement utilisateur principal :** `~/.local/share/herdr/logs/herdr-voice.log` (ou `$XDG_DATA_HOME/herdr/logs/herdr-voice.log`).
    - **Emplacement temporaire de secours :** `${os.tmpdir()}/herdr_voice_system.log`.
  - **Notifications Visuelles Herdr Toast UI :** Transmission directe à l'interface graphique utilisateur via l'API `globalThis.herdr.ui.toast(message, type)` :
    - **`message` (`string`) :** Le texte explicite de l'alerte à afficher dans la bulle d'interface.
    - **`type` (`'info' | 'warn' | 'error' | 'success'`) :** Le niveau de gravité contrôlant la couleur du thème et l'icône visuelle du Toast dans Herdr.
    - **Exemple de code JavaScript (`src/logger.js`) :**
      ```javascript
      // Émission d'une alerte d'erreur de schéma TOML vers le Toast UI Herdr
      if (typeof globalThis.herdr?.ui?.toast === 'function') {
        globalThis.herdr.ui.toast(
          'Configuration error at [server.endpoint]: must match format "uri"',
          'error'
        )
      }
      ```
- En cas d'erreur de configuration ou d'échec réseau, le plugin n'interrompt pas Herdr : il alerte l'utilisateur via le Toast UI et trace l'événement dans le fichier de log.
