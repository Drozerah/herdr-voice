# 003_ADR: Workflow de Développement Local et Enregistrement par Lien Symbolique

- **Statut :** Accepté (Accepted)
- **Auteurs :** Thomas Gauthier & Antigravity (Google DeepMind Team)
- **Date :** 2026-07-26
- **Version du Plugin :** v1.0.0-alpha.1

---

## 1. Contexte & Problématique

Lors du développement d'un plugin pour **Herdr**, le code source doit être géré et versionné au sein d'un dépôt Git local autonome (`./herdr-voice`). 

Cependant, pour être testé en conditions réelles, le plugin doit être chargé par l'exécutable Herdr à travers l'ensemble des workspaces et sessions du système.

Sans mécanisme adapté, le développeur devrait copier manuellement les fichiers compilés vers le dossier global de Herdr (`~/.config/herdr/plugins/`) à chaque modification de code, ce qui créerait une friction importante et un risque d'erreur de version.

---

## 2. Décisions d'Architecture

### D1. Enregistrement Native via `herdr plugin link`
- **Choix :** Le plugin est enregistré auprès de Herdr via la commande CLI officielle :
  ```bash
  herdr plugin link ./herdr-voice
  ```
- **Mécanisme Sous-Jacent :** Cette commande s'appuie sur le mécanisme des liens symboliques Unix (`symlink`), créant un pointeur virtuel entre le registre global `~/.config/herdr/plugins/herdr-voice` et le répertoire de développement local.

### D2. Recompilation en Temps Réel à Chaud (`npm run dev`)
- **Mécanisme :** Le bundler `esbuild` est configuré en mode watch (`esbuild --watch`) via le script `npm run dev`.
- **Réactivité :** À chaque sauvegarde d'un fichier source JavaScript (`src/*.js`), la version distribuée `dist/index.js` est régénérée en moins de 5 millisecondes. Grâce au lien symbolique, la modification est prise en compte instantanément par Herdr sans réinstallation ni redémarrage.

### D3. Équivalence avec les Standards de l'Écosystème
- Le workflow retenu s'aligne exactement sur les normes établies des gestionnaires de paquets modernes (`npm link`, `yarn link`, `bun link`).

---

## 3. Conséquences

### Positives :
- **Friction Zéro en Dev :** Les modifications de code sont testables instantanément en direct dans Herdr TUI.
- **Propreté du Dépôt :** Le code de dev reste isolé dans son propre répertoire Git sans dupliquer de fichiers binaires.
- **Transition Transparente vers la Distribution :** Pour publier le plugin, il suffit d'effectuer un commit/tag Git sans modifier l'organisation des fichiers.

### Neutres :
- Nécessite de laisser tourner le watcher `npm run dev` lors des sessions d'édition active.
