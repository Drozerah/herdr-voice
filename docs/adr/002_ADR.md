# 002_ADR: Architecture et Principes de Conception du Plugin `herdr-voice`

- **Statut :** Accepté (Accepted)
- **Auteurs :** Thomas Gauthier & Antigravity (Google DeepMind Team)
- **Date :** 2026-07-26
- **Version du Plugin :** v1.0.0

---

## 1. Contexte & Problématique

Les utilisateurs d'agents IA exécutant des tâches autonomes ou interactives au sein du multiplexeur de terminal **Herdr** nécessitent un retour vocal temps réel (Text-To-Speech) pour suivre le flux de travail des agents sans garder les yeux fixés en permanence sur l'écran.

Pour garantir une expérience utilisateur fluide, réactive et professionnelle, le plugin vocal doit respecter des contraintes strictes :
1. **Contrôle Réactif :** Bascule instantanée de la sourdine via un raccourci dédié (`Ctrl+v`).
2. **Gestion d'État par Volet :** Isolation totale des états sonores et d'activité entre chaque volet/agent.
3. **Respect de l'Interface TUI Herdr :** Aucune altération des titres d'onglets personnalisés par l'utilisateur.
4. **Interruption Sans Faille :** Destruction instantanée des processus audio en cours lors d'un arrêt ou d'un changement de focus, sans processus zombie.
5. **Distribution Autonome :** Aucun proxy intermédiaire obligatoire, configuration simple et installation en 1 clic.

---

## 2. Décisions d'Architecture

### D1. Langage & Style de Code : Pure JavaScript & JSDoc
- **Choix :** Le plugin est développé à 100 % en **Pure JavaScript (ES Modules `import/export`)**, sans métasyntaxe TypeScript.
- **Typage & Documentation :** Tous les modules JavaScript utilisent scrupuleusement les en-têtes et annotations JSDoc officiels (`@file`, `@description`, `@author`, `@date`, `@param`, `@returns`). La balise `@version` est exclue des en-têtes JS pour maintenir `package.json` comme source de vérité unique (ADR-010).
- **Packaging :** Compilation via `esbuild` vers un fichier bundle unique `dist/index.js` autonome et zéro-dépendance.

### D2. Souveraineté de l'Interface & Séparation UX
- **Titre de l'onglet du haut (`label`) :** **100 % INTACT**. Le plugin n'altère ni ne renomme jamais l'intitulé de l'onglet défini par l'utilisateur (ex: `Master`, `Builder`).
- **Sidebar Latérale (`display_agent`) :** Le plugin intervient exclusivement sur le sous-titre de l'agent dans la sidebar Herdr avec l'identifiant d'agent brut en minuscules et l'icône de statut réactive (`agy 🔊` / `agy 🔈` / `agy 🔇`).

### D3. Événementiel Audio Réel & Interruption Matérielle
- **Pilotage par le Son :** La transition d'icône (`🔈` ➔ `🔊` ➔ `🔈`) est strictement guidée par le début et la fin de l'émission sonore réelle (0 `sleep` artificiel).
- **Interruption Matérielle Instantanée :** Tout appui sur `Ctrl+v` ou changement d'agent actif envoie un signal POSIX `SIGTERM (15)` immédiat sur le lecteur audio (`afplay`), libérant sur-le-champ la carte son, la mémoire RAM et les ressources GPU.

### D4. Configuration Autonome & Point d'Entrée TTS
- **Fichier `config.toml` :** Le plugin embarque son propre fichier de configuration définissant le endpoint d'inférence vocale (ex: `http://localhost:8888/v1/audio/speech` pour `audio-mlx`, Kokoro ou API distante).
- **Indépendance :** Le plugin interagit directement avec l'endpoint TTS et l'API Herdr sans aucun serveur proxy obligatoire.

### D5. Distribution et Workflow Développeur Herdr
- **Développement Local :** Utilisation de la commande native `herdr plugin link ./herdr-voice`.
- **Distribution Open Source :** Installation globale par les utilisateurs en 1 commande `herdr plugin install Drozerah/herdr-voice`.
- **Auto-Updater Intelligent :** Check asynchrone non-bloquant de GitHub Releases (maximum 1x par 24h) avec notification Toast Herdr en cas de nouvelle version disponible.

### D6. Stratégie de Test et Intégration Continue (CI/CD)
- **Tests Unitaires Natifs :** Utilisation du test runner natif Node.js (`node:test` + `node:assert`), sans dépendances lourdes.
- **Mock Serveur Inférence HTTP :** Serveur factice HTTP local pour valider les requêtes en environnement d'intégration.
- **Détection Headless CI :** Détection automatique de `process.env.CI` pour simuler la lecture audio sans carte son matérielle sur GitHub Actions.

## 3. Conséquences

### Positives :
- **Codebase épurée, lisible et performante** que tout développeur JavaScript peut comprendre et faire évoluer sans apprentissage de métasintaxe.
- **Zéro friction pour l'utilisateur final** : installation en 1 clic, 0 `npm install` requis lors de l'utilisation.
- **Stabilité matérielle garantie** sur macOS et compatibilité avec la CI/CD GitHub Actions.

### Neutres :
- La documentation du typage repose sur la rigueur des annotations JSDoc dans le code source.
