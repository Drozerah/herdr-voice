# 007_ADR: Stratégie de Test Unitaire Natif (node:test), Co-location des Tests et Démarrage Événementiel

- **Statut :** Accepté (Accepted)
- **Auteurs :** Thomas Gauthier & Antigravity (Google DeepMind Team)
- **Date :** 2026-07-26
- **Version du Plugin :** v1.0.0-alpha.1

---

## 1. Contexte & Problématique

Pour garantir la qualité, la non-régression et la rapidité d'exécution du plugin `herdr-voice`, la suite de tests doit respecter les principes fondamentaux du projet :
1. **Zero-Dependency :** Ne pas alourdir les dépendances avec des frameworks tiers lourds.
2. **Productivité Développeur (DX) :** Permettre au développeur d'évaluer visuellement et immédiatement la couverture de code (coverage) dans son arborescence de fichiers.
3. **Fiabilité CI/CD (Zero Flaky Test) :** Éliminer les timeouts fixes arbitraires susceptibles de provoquer des échecs intempestifs sur les serveurs d'intégration continue.

---

## 2. Décisions d'Architecture

### D1. Adoption du Test Runner Natif Node.js (`node:test` & `node:assert`)
- **Choix :** Tous les tests unitaires et d'intégration utilisent exclusivement le test runner natif de Node.js (`node:test`) et le module d'assertion strict (`node:assert/strict`).
- **Raison du Choix :** Zero-dependency externe, exécution en quelques millisecondes et compatibilité native avec les runners CI/CD (GitHub Actions).

### D2. Co-location des Fichiers de Test (Colocated Testing)
- **Placement :** Les fichiers de test sont placés directement à côté du module source qu'ils testent (ex: `src/config.js` ➔ `src/config.test.js`, `bin/mock-tts-server.js` ➔ `bin/mock-tts-server.test.js`).
- **Avantages :** 
  - Estimation visuelle instantanée du coverage dans l'arborescence IDE.
  - Proximité du code et du test lors des phases de refactoring.
  - Raccourcissement des chemins d'importation relatifs.

### D3. Commande NPM Unique
- **Script :** Le script `"test": "NODE_ENV=test node --test src/index.test.js bin/mock-tts-server.test.js bin/version-sync.test.js"` est enregistré dans `package.json` avec l'énumération explicite des fichiers de test pour garantir la compatibilité entre versions Node.js (18/20/22) en CI.

### D4. Démarrage Événementiel Déterministe (`Ready Event`) & Portabilité `os.tmpdir()`
- **Zéro Timeout Arbitraire :** Interdiction des `setTimeout` fixes dans les étapes `before()` des tests. L'attente du démarrage d'un serveur child s'effectue exclusivement par détection événementielle du message de disponibilité (`stdout` Ready Event), évitant 100 % des "flaky tests" en CI/CD et réduisant le temps d'exécution à 80 ms.
- **Portabilité des Fichiers Temporaires :** Les tests et les serveurs utilisent le répertoire temporaire système natif `os.tmpdir()` (`path.join(os.tmpdir(), ...)`), garantissant une exécution sans conflit d'I/O sur macOS, Linux et Windows.

---

## 3. Conséquences

### Positives :
- Boucle de rétroaction visuelle immédiate pour le développeur.
- Suite de tests ultra-rapide (80 ms), totalement déterministe et indépendante de packages tiers.
